# WhaleFollow — памятка для Claude

Аналитический агент для Polymarket: находит сильных игроков («китов»), проверяет, что их результат —
умение, а не удача, и предлагает повторять их ставки. **Ставки только виртуальные** (paper); реальная
торговля отключена (`LiveBroker` бросает исключение) и остаётся отключённой.

Пользователь пишет по-русски; интерфейс, README и итоги — на русском, простым языком.
Файл `.env` пользователя никогда не попадает в архивы и коммиты.

## Запуск и проверка
- `pip install -e ".[dev]"`, тесты: `python -m pytest -q` (≈200 тестов, ~80 с, без сети —
  синтетический мир в `tests/synthetic.py`).
- Docker: `docker compose up --build` — три процесса (`api`, `realtime`, `worker`) + шаг `migrate`, интерфейс на :8787, база в томе `/data`.
- Тесты на PostgreSQL: `WF_TEST_PG=postgresql://... python -m pytest -q` (каждая база теста — своя схема; `@pytest.mark.sqlite_only` — только SQLite).
- CLI: `whalefollow api | realtime | worker` (роли), `whalefollow run` (всё в одном), `whalefollow check`, `whalefollow alive <роль>`.
- Интерфейс: `cd frontend && npm ci && npm run check && npm run build` (сборка → `whalefollow/web`, её коммитим);
  сценарии: `WF_PYTHON=../.venv/bin/python npx playwright test` (демо-сервер `tests/demo_server.py`, без сети).

## Важные договорённости
- Данные собираются только по китам из списка пользователя (`tracked.py`, `auto_discover` выключен).
- Новые источники, каналы уведомлений и стратегии — плагинами (`whalefollow/plugins/`), а не правкой ядра.
- Polymarket Data API — только v2 (v1 отключён, HTTP 410). Справка: `https://data-api.polymarket.com/v2/openapi.json`.
- Комиссия тейкера: `акции × ставка × p × (1−p)`, ставки по темам — в `fees.py`.
- Всё «на момент now», без заглядывания в будущее. Чек-лист ошибок — навык `trading-math-audit`.
- Выпуск версии — навык `whalefollow-release`; проверка интерфейса — навык `whalefollow-ui-check`.
- Качество: `ruff check . && ruff format --check . && mypy` (настройки в `pyproject.toml`), pre-commit, CI в `.github/workflows/ci.yml`.
- Эталон расчётов — `tests/golden` (пересоздаётся только при сознательной смене формулы: `python tests/golden/make_golden.py`).
- Схема базы меняется только новой миграцией (`alembic revision -m ...`), `schema.sql` не правится.
- Версия — в двух местах: `whalefollow/__init__.py` и `pyproject.toml`. История — разделы «Что нового» в README.

## Мажорное обновление 1.0 — план работ

**Как работать по плану.** Выполняй этапы строго по порядку, начиная с этапа 1. Этап считается
законченным, только когда выполнены все его критерии готовности. После каждого этапа:
тесты зелёные → выпуск версии (навык `whalefollow-release`: минорная версия, раздел в README, архив без `.env`)
→ короткий итог пользователю по-русски → отметь этап здесь как выполненный (`[x]`) и переходи к следующему.
Если решение необратимо или неоднозначно (удаление данных пользователя, смена формата базы без миграции,
отказ от функции) — остановись и спроси. Перед установкой нового пакета проверь, что он поддерживается
и подходит по лицензии; версии фиксируй в `pyproject.toml` / `package.json`.

Общие правила для всех этапов:
- Никакой регрессии: всё, что есть сейчас (экраны, сигналы, потоки, диагностика, вход по паролю,
  Telegram, «что было бы», рейтинг, пачечное добавление), работает и после этапа.
- Существующая база пользователя обновляется без потерь (проверять на копии реальной базы, если она есть в `/data`).
- Расчёты не меняются молча: если меняется формула — тест «было → стало» и строка в README.
- Новый код — с типами и тестами; тяжёлые модули читать частями.

## Модуль «События» — план работ (версии 1.1–1.5)

Новая вкладка «События»: событие Polymarket → независимая оценка вероятностей исходов → сравнение с ценой →
совет «что купить, по какой цене, сколько». Отдельно от модуля китов, ничего существующего не ломать.
Работать по этапам A→E по тем же правилам, что план 1.0 (тесты → выпуск минорной версии → README → итог → `[x]` →
сразу влить в `main`). Ставки только виртуальные.

Решения пользователя: подробные данные — только по событиям, которые открыли или за которыми следят (каталог —
из кэша); дневной лимит анализов с ИИ (настройка); **общий банк, отдельный лимит** для ставок по событиям
(`events_daily_limit_usd`, `events_max_bet_usd`; стопы по убытку — общие); ключи внешних источников — по мере надобности.
Два режима, как у сигналов: **с ИИ** и **без ИИ** — во втором всё то же, вероятность считает аналитическая модель.

Главный принцип: цену рынка обыграть трудно. Итог = цена + λ·(оценка модели − цена); λ мал (≈0,3), пока модель
не доказала на закрытых событиях, что точнее рынка (Brier), и растёт с доказанной точностью по теме.
Всё «на момент анализа», без заглядывания вперёд. Проверка ИИ на прошлом недопустима (модель могла знать исходы) —
только вперёд, в пробном режиме.

### Аналитическая модель (`whalefollow/eventhub/`)
Оценщики — плагины нового вида `EstimatorPlugin` (`applies(event, market)`, `estimate(ctx, dossier) → p, качество,
объяснение`). Входы модели без ИИ:
| Блок | Что берём | Как используем |
|---|---|---|
| Рынок Polymarket | цена, спред, стакан, объём, ликвидность, история цен, срок, сумма цен исходов (neg-risk) | поправленная цена: кривая калибровки «цена → частота исхода» по закрытым рынкам нашей базы (по теме и сроку; эффект «маловероятное переоценено»); нормировка суммы исходов; тонкий рынок — меньше вес |
| Другие площадки | Kalshi, Manifold, Metaculus, букмекеры без маржи | консенсус, вес — по объёму/числу прогнозистов и уверенности сопоставления вопроса |
| Расчётные модели по темам | крипто: цена + ожидаемая волатильность опционов → вероятность выше/ниже порога к дате (и «касание»); спорт: букмекеры, позже рейтинги; погода: доля членов ансамбля прогноза (Open-Meteo); экономика: консенсус-прогноз + разброс прошлых отклонений; политика: средние опросов + историческая ошибка опросов; «случится ли к дате»: базовая частота и убывание со временем | собственная вероятность исхода |
| Сильные игроки | позиции проверенных китов и держателей с лучшей прибылью | небольшой сдвиг, вес — по прошлой пользе |
| Новости (без ИИ) | поток статей, свежесть, всплеск относительно обычного | направление не определяем; всплеск = «цена может быть устаревшей» → шире неопределённость, меньше ставка |
Сведение: средневзвешенное в логитах (веса — по прошлой точности оценщика в теме × качество данных), поправка
«экстремизации» (по калибровке), затем сжатие к цене рынка (λ); многоисходные события — сумма вероятностей = 1.
Неопределённость: разброс оценщиков + качество данных → «низкая/средняя/высокая» и интервал.
Режим с ИИ: тот же конвейер + оценщик Claude вслепую (видит правила, досье и расчёты, но не цены площадок),
несколько ответов → медиана; ИИ также пишет объяснение и «что изменит оценку». Без ИИ объяснение собирается по шаблонам.
Совет: по каждому исходу «Да» и «Нет»: выгода = оценка − цена − комиссия; порог растёт с неопределённостью и сроком
(годовая доходность); сумма — ¼ Келли с комиссией → лимиты модуля и общие → проход по стакану; предельная цена заявки.
