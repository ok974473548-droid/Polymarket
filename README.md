# WhaleFollow — бэкенд и агент (v1.2)

Система находит на Polymarket игроков со статистически подтверждённым преимуществом,
следит за их новыми ставками и решает, можно ли их ещё выгодно повторить.
Реализация следует ТЗ «WhaleFollow: агент отбора и копирования ставок на Polymarket».

**В этой версии ставки только бумажные (виртуальные деньги).** Реальное исполнение
заблокировано в коде (`LiveTradingDisabled`) до приёмки пробного режима и юридической
проверки (разделы 12–13 ТЗ).

## Быстрый старт (Docker)

```bash
cp .env.example .env                              # при необходимости впишите ключ Claude и бота Telegram
docker compose run --rm api whalefollow check     # проверка доступа к Polymarket
docker compose up -d --build                      # http://localhost:8787
docker compose logs -f                            # журнал всех трёх процессов
```

Программа работает только на реальных данных Polymarket. Ставки виртуальные до
выполнения критериев приёмки (экран «Итоги → Как идёт пробный режим»).
При первом запуске система сама ищет кандидатов, загружает их историю и строит список
китов — прогресс виден в баннере на экране «Сигналы».

Автотесты (для разработки) работают на синтетическом рынке из `tests/synthetic.py`,
где заранее известно, кто «умный», а кто случайный; в программу он не входит:

```bash
docker compose run --rm api python -m pytest -q
```

## Работа с реальным Polymarket

```bash
export WF_DB_URL=sqlite:///whalefollow.db        # или postgresql://… (pip install -e ".[postgres]")
whalefollow init-db
whalefollow sync-markets                         # каталог и исходы
whalefollow ingest --global                      # свежая лента — источник кандидатов
whalefollow ingest --wallets-file wallets.txt    # полная история кандидатов
whalefollow sync-prices --days 365               # история цен для CLV
whalefollow build                                # позиции + антисибил
whalefollow score                                # скоринг и живой список
whalefollow backtest --select-days-ago 60        # главный вопрос: зарабатывает ли копия
whalefollow walkforward --months 6
whalefollow serve --with-agent                   # API + агент в фоне (бумажные ставки)
whalefollow serve --with-agent --llm             # + слепая оценка Claude (ANTHROPIC_API_KEY)
```

Рекомендуемое расписание (cron/планировщик): `sync-markets` каждые 5–10 мин,
`snapshot-books` каждые 10–30 с по рынкам китов, `sync-prices` раз в час,
`build` и `score` раз в сутки. **Запись стаканов запускайте с первого дня**:
задним числом их не получить, а без них бэктест только оптимистичный.

Параметры (раздел 14 ТЗ) меняются JSON-файлом `--params params.json` или переменными
`WF_<ИМЯ>` (например `WF_EDGE_THRESHOLD=0.04`). Версия набора параметров пишется в
каждое решение.

## Пробный режим (этап 6 ТЗ)

```bash
docker compose up -d --build      # интерфейс: http://localhost:8787
docker compose logs -f            # журнал
```

Один процесс `whalefollow run` делает всё сам:

| Задача | Как часто | Что делает |
|---|---|---|
| Агент | 5 с | Страница общей ленты сделок + несколько китов по кругу → сигналы → решения |
| Стаканы | 20 с | Снимки по нашим ставкам, ждущим сигналам и открытым позициям китов |
| Каталог рынков | 10 мин | Открытые рынки |
| Поиск кандидатов | 15 мин | Самые активные кошельки свежей ленты → полная история |
| Исходы | 30 мин | Рынки, срок которых прошёл, и рынки наших ставок |
| Цены | 1 ч | История для новых токенов (часовая) и свежая для активных |
| Пересчёт китов | сутки | Позиции → антисибил → скоринг → живой список |
| Итоги недели | неделя | Уведомление |

Первый проход сразу после старта набирает кандидатов и строит первый список китов —
от нескольких минут до часа. Прогресс виден на экране «Итоги → Как идёт пробный режим»:
200 сигналов, 4 недели, калибровка ±5 п.п. в корзинах с 30+ исходами, просадка ≤ 15%.
Калибровка считается по всем рекомендациям «купить» с известным исходом, включая
пропущенные вами — проверяется прогноз системы, а не ваши решения.

**Telegram.** Заполните в `.env` `WF_TELEGRAM_BOT_TOKEN` (бот от @BotFather) и
`WF_TELEGRAM_CHAT_ID` (подскажет @userinfobot), перезапустите сервис. Сигналы,
выход кита, паузы и итоги недели придут со ссылкой на нужный экран. Что присылать —
в «Настройки → Уведомления». Если подтверждать сигналы некогда, в пробном режиме
можно выключить «Подтверждать каждую ставку вручную»: агент будет покупать сам
(виртуальными деньгами).

## Режимы «с ИИ» и «без ИИ» (этап 7 ТЗ)

| | С ИИ | Без ИИ |
|---|---|---|
| Сбор и анализ данных (киты, цены, стакан, скоринг) | да | да |
| Новости (Google News) и другие рынки прогнозов (Manifold) | да | да |
| Слепая оценка Claude с аргументами «за» и «против» | да | нет |
| Кто принимает решение | система рекомендует, вы подтверждаете (или автопокупка в пробном режиме) | всегда вы |

Режим выбирается в «Настройки → Кто принимает решение». ИИ доступен, если в `.env`
задан `ANTHROPIC_API_KEY`; без ключа система сама работает без ИИ. Если ИИ не ответил,
сигнал переходит в режим «решение за вами», приходит уведомление. Каждая оценка ИИ
сохраняется: после 300 рынков с исходом видно, точнее ли он рыночной цены. Пока не
доказал — его вес в решении снижен (25%), а при расхождении с китом больше 10 п.п.
сигнал пропускается.

В карточке сигнала: оценка ИИ (если включён), «Данные для решения» (цена кита, цена
сейчас, шанс по истории кита, его результаты), другие рынки прогнозов, новости с
пометкой «надёжный источник / непроверенный» и предупреждения о возможном вбросе.

## Блокчейн, Telegram-каналы и соцсети (шаг 4)

**Переводы USDC (антисибил L1 «общий источник денег» и L2 «прямые переводы»).**
Система раз в 30 минут загружает переводы USDC в сети Polygon для кандидатов: сначала
живой список и допущенные киты, потом остальные (до 60 кошельков за проход, обновление раз
в 30 дней). Нужен обозреватель блокчейна — впишите в `.env` один из вариантов:

```
WF_ETHERSCAN_API_KEY=ваш_ключ          # Etherscan API v2, ключ бесплатный: etherscan.io/myapikey
# или
WF_CHAIN_PROVIDER=blockscout           # Blockscout, можно без ключа (с ключом — выше лимиты)
WF_BLOCKSCOUT_API_KEY=                 # необязательно
```

Бесплатный тариф Etherscan покрывает не все сети; если `whalefollow check` или журнал
покажут ошибку доступа к Polygon, переключитесь на Blockscout. Статус подключения виден в
«Настройки → Источники данных», ход загрузки — на экране «Пробный режим» (задача
«Переводы USDC»). Без обозревателя антисибил работает по сигналам L3–L6.
Адреса бирж и мостов, которые пополняют тысячи кошельков, автоматически не считаются
связью (больше 20 кошельков у одного источника); известные адреса можно добавить в
параметр `funder_allowlist`. Почему кошельки объединены в одного игрока — в профиле кита,
блок «Почему это один игрок».

**Telegram-каналы.** В «Настройки → Источники данных» впишите публичные каналы через
запятую или с новой строки: `@fednews`, `t.me/channel` или полную ссылку. Система ищет в
веб-версии канала (`t.me/s/<канал>`) сообщения по ключевым словам вопроса рынка. Ключ и
бот не нужны, но работают только публичные каналы с включённым веб-просмотром. Сообщения
помечаются как непроверенные (вес 0,2) и служат поводом проверить новость, а не доказательством.

**Соцсети (Reddit).** Флажок «Соцсети (Reddit)» в тех же настройках: обсуждения за неделю
через публичный поиск Reddit, вес 0,2. X (Twitter) не подключён: его API платный.

## Что нового в v1.6 — теневые анализы для самообучения (точность модели, этап F1)

Модель учится только на закрытых событиях. Раньше анализ сохранялся, лишь когда вы открывали событие, — это единицы
исходов в неделю. Теперь модель сама собирает данные для самопроверки — **теневые анализы**:
- раз в 6 часов набирается выборка событий по всем темам: половина — те, что скоро закрываются (исходы придут
  быстрее), половина — самые крупные за сутки; только с объёмом от $10 000 и закрывающиеся не раньше чем через 6 часов
  и не позже чем через 120 дней;
- по каждому событию — досье и оценка модели без ИИ (бесплатно), до 12 исходов с ценой от 2% до 98%;
  анализ сохраняется с ценой рынка на тот момент и пометкой «теневой»;
- процесс `worker` разбирает очередь порциями: до 12 событий и не дольше 4 минут раз в 15 минут, чтобы не мешать
  остальной работе; факты досье старше 45 дней удаляются (оценки уже сохранены в анализах).

Настройки — «Настройки» → «Сбор данных»: включить или выключить, сколько событий на тему (по умолчанию 10) и как часто
(раз в 6 часов). На экране «Точность модели событий» — новый блок «Сбор данных для самообучения»: сколько событий
разобрано, сколько уже закрылось, сколько ждёт закрытия.

Проверено на живом Polymarket: за один круг выбрано 90 событий по 9 темам, сохранены анализы по 374 исходам,
около 1,8 с на событие. Через 1–2 месяца наберутся тысячи закрытых исходов — на них настраиваются следующие этапы.
Честно о текущем состоянии: независимые оценки пока есть в основном у крипты и погоды; в остальных темах модель почти
всегда повторяет цену рынка — это закрывают следующие этапы (согласованность рынков, спорт, сверка вопросов ИИ).
База обновляется миграцией (у анализа появилась пометка, откуда он: страница, «Следить» или теневой).

## Что нового в v1.5 — самопроверка модели событий (модуль «События», этап E)

Новый экран **«Точность модели событий»** (кнопка «Точность модели» на вкладке «События», ссылка из «Итогов»).
Он честно показывает, обыгрывает ли модель цену рынка.

**Как проверяется.** Каждый анализ сохраняется вместе с ценой рынка на тот момент (так было с v1.3). Раз в час процесс
`worker` узнаёт исходы закрывшихся рынков. Сравниваются только анализы, сделанные до закрытия: чья вероятность была
ближе к исходу — итога модели или цены рынка (Brier: чем меньше, тем точнее). Если по одному исходу было много
анализов, вместе они весят как один. Вывод:
- **«Мало данных»** — закрыто меньше 30 исходов;
- **«Лучше рынка»** — только если разница больше двух ошибок (ошибка считается по событиям: исходы одного события связаны);
- **«Хуже рынка»** — так же строго в обратную сторону;
- иначе **«Пока не лучше рынка»**.
Режимы «с ИИ» и «без ИИ» — отдельно; оценки ИИ проверяются только вперёд (на прошлом ИИ мог знать исходы).
На экране также калибровка («когда модель говорит 70%, как часто сбывается»), точность по темам, по каждому оценщику
(помогала ли его поправка цене) и результат ставок по событиям.

**Обучение — только по закрытым событиям.**
- λ (насколько итог может отойти от цены) подбирается по прошлым анализам и сжимается к исходным 30%: при малом
  числе исходов почти не меняется. Если по теме закрыто 50 исходов и больше — у темы свой λ.
- Вес каждого оценщика умножается на 0,2–2: поправка в прошлом улучшала цену — больше, ухудшала — меньше.
- **Расти λ и веса могут, только когда модель доказанно точнее рынка** (вывод «Лучше рынка» по тем итогам, что
  показывались тогда). Снижаться — всегда: осторожность доказательств не требует.
- Модель сразу берёт выученное: в объяснении пишется, по скольким закрытым исходам подобран λ.

Проверено на живом Polymarket: закрывшиеся рынки из сохранённых анализов находятся за доли секунды, исходы
учитываются, при 2–3 закрытых исходах экран честно пишет «Мало данных». В демо — 80 синтетических закрытых исходов:
модель на 1,6% точнее цены, но в пределах случайности → «Пока не лучше рынка», λ остаётся 30%.
База не менялась (используются таблицы анализов, рынков и исходов); выученные параметры хранятся в состоянии системы.

**Исправление (модуль китов):** при добавлении игроков пачкой с «копировать после проверки» параллельные проверки
могли потерять друг у друга отметку, а быстрая проверка — закончиться раньше, чем игрок попадал в список. Тогда
копирование не включалось, хотя игрок проверку прошёл. Теперь список записывается до запуска проверок и правится
под замком.

## Что нового в v1.4 — советник (модуль «События», этап D)

На странице события над исходами — карточка **«Совет модели»**: что купить, по какой цене и сколько.
Например: «Купить «Да» в «Вера Ли» на $15,70 по цене до 18,8¢». Под ней три сценария: «если сбудется» (+$68,63),
«если нет» (−$16,21) и «в среднем по оценке» (+$4,31). Кнопка **«Поставить по совету»** открывает виртуальную покупку
с уже подставленными суммой и предельной ценой. Если выгодных ставок нет, карточка так и говорит и показывает, что
ближе всего к выгоде и по какой цене станет выгодно. Во вкладке «Модель» у каждого исхода видно, почему «Да» и «Нет»
выгодны или нет.

**Как считается совет** (по каждому исходу — обе стороны, «Да» и «Нет»):
- цена акции с комиссией: лучшая цена продавца + комиссия тейкера Polymarket (акции × ставка × p × (1−p));
- выгода = оценка модели − цена с комиссией;
- выгода должна быть не меньше **2 п.п. + половины полуширины интервала оценки** — чем менее уверена модель,
  тем больше нужен запас;
- и **не меньше 15% годовых**: 3 п.п. за событие через два года не стоят замороженных денег;
- **предельная цена** — самая высокая цена, при которой оба условия ещё выполняются; дороже покупка не идёт;
- **сумма — ¼ Келли с комиссией** от банка, затем лимиты «Событий» (на одну ставку и в день) и общие лимиты и паузы,
  затем проход по стакану только по уровням не дороже предельной цены;
- если у исхода нет независимых оценок, совета нет: обыграть цену нечем.

**«Следить»** (кнопка на карточке): процесс `worker` раз в 15 минут проверяет событие — собирает досье, считает
модель и совет — и присылает уведомление (колокольчик, push, Telegram и другие каналы), когда появилась выгодная ставка
или выгода выросла на 2 п.п. Включается в «Настройках» → «О чём уведомлять» → «Выгода в событиях». Список событий,
за которыми следите, — вверху вкладки «События»; закрытые события перестают проверяться сами.

**Учёт отдельно от китов:** ставки по совету помечены в «Моих ставках» как «по совету модели», свои ставки по событиям —
«своя ставка по событию». В «Итогах» появился блок «Ставки по событиям»: по совету модели и свои — сколько ставок,
выиграно, проиграно, результат.

## Что нового в v1.3 — модель оценки событий (модуль «События», этап C)

На странице события — вкладка **«Модель»** (открывается первой) и у каждого исхода метка **«модель 31%»**: собственная
оценка вероятности рядом с ценой Polymarket. На графике цены — пунктир: оценка модели во времени. Всё обновляется само:
досье собирается в фоне (если его нет или оно старше 30 минут), оценка пересчитывается раз в минуту.

**Как считается (одинаково в режимах «с ИИ» и «без ИИ»):**
1. **Якорь — цена Polymarket сейчас** (середина спроса и предложения).
2. **Независимые оценки** — плагины нового вида «Модели оценки» (экран «Плагины»), каждая по досье события:
   - *Другие площадки прогнозов* — Kalshi, Manifold, Metaculus. Прогноз, расходящийся с ценой больше чем на 30 п.п.,
     отбрасывается (почти всегда это другой вопрос), как и один прогноз, найденный сразу к нескольким исходам;
   - *Крипто: порог цены к дате* — цена монеты и ожидаемая волатильность опционов → вероятность коснуться порога или быть
     выше/ниже него к дате (логнормальная модель); для порогов далеко от цены доверие снижается — такая модель занижает «хвосты»;
   - *Погода: ансамбль прогнозов* — доля 31 варианта прогноза GFS, попадающих в каждый исход;
   - *Перевес сделок за сутки* — показывается, но пока с весом 0;
   - *ИИ вслепую (Claude)* — только в режиме «с ИИ»: видит правила, новости и данные досье, **но не цены**; три ответа →
     середина; пишет главные доводы и «что изменит оценку». Анализ идёт в фоне, лимит — «Настройки» → «События: анализов
     с ИИ в день» (по умолчанию 30). Без ключа `ANTHROPIC_API_KEY` работает режим «без ИИ».
3. **Сводная оценка** — среднее в логитах с весами (вес оценщика × качество данных).
4. **Итог = цена + λ·(сводная − цена)**, λ = 0,3 × сила данных. Итог отходит от цены не больше чем на 30% разницы, пока на
   закрытых событиях не доказано, что модель точнее рынка (этап E будет подбирать λ и веса по точности).
5. Взаимоисключающие исходы: сумма итогов равна сумме цен; исходы без оценок уступают место пропорционально.
6. **80% интервал и уверенность** — по разбросу оценщиков и количеству данных; всплеск свежих новостей расширяет интервал.

Во вкладке — «лестница» по каждому исходу: цена → каждая оценка с весом и основанием → сводная → итог; объяснение
словами (без ИИ — по шаблону, с ИИ — доводы Claude). Каждый анализ сохраняется (не чаще раза в 10 минут на событие) —
для будущей самопроверки.

**Проверка на истории закрытых рынков (честно):**
- *Поправка цены по истории* («при цене 10¢ сбывалось в 7%»). Кривые построены на 2432 закрытых рынках Polymarket (5505
  точек за 1, 7 и 30 дней до закрытия), проверены вне выборки (70% ранних → 30% поздних, 1652 точки): Brier цены как есть —
  0,0463, с поправкой — 0,0465. **Не лучше** — поэтому плагин «Цена с поправкой» выключен; его можно включить для опыта.
- *Консенсус Manifold* к той же цене на тот же момент (522 пары по 210 рынкам). Без отбора смешивать с Manifold вредно
  (Brier 0,0368 → 0,0498 даже при весе 25%; один Manifold — 0,26: находятся похожие, но другие вопросы). С отсечкой «расхождение не больше 30 п.п.» (376 пар,
  154 рынка): цена Polymarket — 0,0352, Manifold — 0,0374, смесь с осторожным весом — 0,0336–0,0338. **Небольшая польза
  есть только с отсечкой** — так модель и устроена.
- Крипто- и погодная модели на истории пока не проверены — у них небольшой вес; проверит самопроверка (этап E).

Совет «что купить, по какой цене и сколько» — следующий этап (D). База обновляется миграцией (таблица анализов
`event_analyses`); расчёты сигналов китов не менялись. Новые переменные `.env`: `WF_EVENTS_LLM_MODEL` (если не задана —
`WF_LLM_MODEL`), `WF_EVENTS_AI_SAMPLES` (ответов ИИ на анализ, по умолчанию 3). Для режима «с ИИ» добавлен официальный
пакет `anthropic` (лицензия Apache-2.0).

## Плагины: как добавить свой

Плагин — класс Python с уникальным `name`, наследник одного из трёх видов (`whalefollow.plugins`):

| Вид | Что реализовать | Когда вызывается |
|---|---|---|
| `SourcePlugin` | `news(ctx, query, since_ts)` → список `NewsItem` и/или `forecasts(ctx, question, market)` → список `Forecast`; по желанию `sync(ctx)` + `sync_interval_s` | при проверке сигнала; `sync` — фоновой задачей в процессе `worker` |
| `NotifierPlugin` | `send(ctx, notice)`; по желанию `kinds` (какие уведомления) и `start(ctx, services)` (приём команд) | на каждое уведомление из колокольчика, в своём фоновом потоке |
| `StrategyPlugin` | `accept(candidate)` → `Verdict(ok, "причина")` | на каждую новую покупку кита на копировании; и в бэктесте |

Общие поля: `title`, `description` (для экрана), `default_enabled`, `requires_env` (переменные окружения, без
которых плагин недоступен). Кандидат стратегии (`Candidate`) — кит, исход, цена и сумма покупки на момент `ts`;
`candidate.buyers(window_s)` — какие киты из вашего списка купили тот же исход за окно (только прошлое).

**Одним файлом** — положите `.py` в папку плагинов и перезапустите приложение:
- Docker: `/data/plugins/` (том с базой), например `docker compose cp my_plugin.py api:/data/plugins/`
  и `docker compose restart`;
- без Docker: папка `plugins/` рядом с местом запуска или своя — `WF_PLUGINS_DIR`.

```python
# plugins/big_bets.py
from whalefollow.plugins import Candidate, StrategyPlugin, Verdict


class BigBetsOnly(StrategyPlugin):
    name = "big_bets"
    title = "Только крупные ставки"
    description = "Сигнал, только если кит купил минимум на $5 000"

    def accept(self, c: Candidate) -> Verdict:
        return Verdict(c.size_usd >= 5000, f"покупка на ${c.size_usd:.0f}")


PLUGINS = [BigBetsOnly()]
```

Готовый пример всех трёх видов (RSS-лента, журнал уведомлений в файл, стратегия «крупные ставки») —
`examples/plugins/example_plugins.py`. **Пакетом** — объявите entry point в группе `whalefollow.plugins`:

```toml
[project.entry-points."whalefollow.plugins"]
my_plugins = "my_package.plugins:PLUGINS"
```

Ошибки плагина не роняют приложение: при загрузке они видны вверху экрана «Плагины», при работе — в строке
плагина. Плагин работает с правами приложения — ставьте только те, которым доверяете.

**совпадают со старыми** до девятого знака — это проверяет тест-сверка с эталоном, снятым на версии 0.15.

| Синтетический мир: 3000 событий, 320 кошельков | v0.15 | v0.16 |
|---|---|---|
| Полный пересчёт китов (настройки тестов: 1000 пересборок) | 10,3 с | 3,6 с |
| Полный пересчёт китов (боевые настройки: 10 000 пересборок) | 16,1 с | 9,3 с |
| Бэктест | 10,3–11,4 с | 2,7–2,8 с |

С боевыми настройками основное время теперь — сами статистические пересборки (бутстреп): их порядок случайных
чисел не меняли, чтобы результаты совпали со старыми.

**Пересчёт только изменившихся китов.** Раз в час пересчитываются киты, у которых появились сделки, исходы
рынков или изменился состав кошельков; раз в сутки — все (часть показателей зависит от даты: окно 90 дней,
«активен ли»). На том же мире: полный пересчёт 7,6 с, изменились 3 кита из 322 — 0,29 с, ничего не
изменилось — 0,03 с.

**Тесты-инварианты** (hypothesis): на случайных данных проверяется, что позиция не теряет больше вложенного,
продажи не превышают покупок, порядок сделок не влияет на итог, комиссия симметрична и максимальна при 0,5,
проход по стакану не дешевле лучшей цены, наша цена в «что было бы» не лучше цены кита, дневной лимит соблюдён.

Исправлено (было → стало):
- **PostgreSQL:** дробные числа хранились в 32 битах (~7 знаков) — цены и суммы теряли точность. Стало: 64 бита,
  как в SQLite; уже созданные базы PostgreSQL переводятся миграцией (потерянные знаки не вернуть). SQLite не затронута.
- **Проход по стакану:** уровень с ничтожным объёмом («пыль») давал среднюю цену 0. Стало: такие уровни пропускаются.

pandas больше не нужен; новые пакеты: polars, DuckDB, pyarrow (для разработки — hypothesis), версии закреплены.

## Что нового в v0.15 — три процесса вместо одного (этап 2 обновления 1.0)

Раньше всё работало в одном процессе: когда ночью пересчитывались киты, тот же процесс принимал сделки

  | без пересчёта | 6,3 мс | 9,6 мс | — |

- Всё в одном процессе, как раньше, тоже работает: `whalefollow run`.

## Исправления v0.13.1 — аудит алгоритмов

Расчёты:
- **Оценка «по киту» без двойного счёта.** Раньше шанс считался как «цена сейчас + преимущество кита»:
  если цена после его сделки выросла, его преимущество прибавлялось к уже выросшей цене. Теперь —
  от его цены входа (или от текущей, если цена упала — так осторожнее).
- **Келли с комиссией:** доля ставки считается от цены акции вместе с комиссией.
- **Одна заявка кита — один сигнал.** Крупная заявка, разобранная по нескольким мейкерам, приходила
  несколькими сделками и давала несколько сигналов и покупок; «убеждённость» считалась по кусочку.
  Теперь исполнения одной транзакции склеиваются (сумма и средняя цена), повтор по тому же исходу в
  течение 10 минут не создаёт сигнал, докупка кита при нашей открытой позиции — «уже в позиции».
- **«Кит вышел» — только когда вышел.** Раньше любая продажа (даже 10% позиции) давала запрос «кит вышел»,
  и каждая следующая продажа — ещё один. Теперь — когда у кита осталось не больше 10% купленного, один раз.
- **Отбор китов: поправка на множественные проверки** считается по всем проверенным игрокам, а не только
  по пересчитываемым сейчас (у одиночной проверки q было равно p — «везунчик» проходил легче).
- **Позиции:** продажа акций, полученных не покупкой (split, перевод), больше не завышает прибыль;
  позиции в рынках без даты разрешения больше не выпадают из оценки.
- **Маркет-мейкеры:** split/merge стал отдельным признаком (раньше признак не считался вовсе), а сами
  split больше не выглядят «двусторонней торговлей».
- **Исходы рынков:** оспоренный рынок не рассчитывается до конца спора; рынок «50 на 50» платит по 0,5
  (раньше такие ставки висели открытыми навсегда).
- **Мои ставки и итоги:** прибыль открытой ставки учитывает уже проданную часть; итоги — с комиссиями и
  без двойного счёта одной позиции; повторный вход в закрытую позицию снова считается открытым.
- **Точность ИИ** сравнивается с рынком на одних и тех же рынках (раньше — на разных наборах).
- **«Что было бы»:** если истории цен нет, выход следом за китом считается по цене его продажи;
  результат самого кита — по его цене выхода.
- **Антисибил:** пересчёт по своим кошелькам не стирает чужие объединения; если объединение кошельков
  распалось, кит в списке переносится на основной кошелёк (раньше молча переставал отслеживаться).

## Что нового в v0.13 — готовые данные Polymarket и удобный интерфейс

**Меньше своих расчётов.** Polymarket сам считает прибыль игрока, позиции, объём, стоимость портфеля
и место в рейтинге — теперь это берётся готовым (`/v2/user-pnl`, `/v2/user-stats`, `/v2/user-volume`,
`/v2/value`, `/v2/leaderboard?user=`, `/v2/positions`, `/v2/holders`), с кэшем в памяти на 5 минут:
- карточка любого игрока строится за 1–2 секунды без загрузки его истории;
- **сверка с Polymarket убрана** из проверки игрока и из ночных задач (цифры и так у Polymarket) —
  этап, на котором проверка зависала, больше не существует;
- глубокая проверка (история сделок → можно ли копировать с задержкой) остаётся своей: её Polymarket
  не считает. Идёт в фоне, не больше двух одновременно.

**Добавление игроков.**
- Поиск по ссылке на профиль (`polymarket.com/profile/0x…`, `polymarket.com/@имя`), адресу или имени.
- Сразу — карточка: прибыль за всё время / 30 / 7 дней, объём, стоимость позиций, рынков, крупнейший
  выигрыш, просадка, кривая прибыли (7/30/90 дней, всё время), форма по неделям, открытые позиции.
- «Добавить и копировать»: игрок попадает в список сразу, копирование включается само, если пройдёт
  проверку (иначе останется «Только следить», придёт уведомление).
- Рейтинг с галочками: отметить нескольких (или всю страницу) и добавить пачкой.

**Боковая панель и мини-карточки.** Клик по игроку в рейтинге, среди держателей рынка или по киту в
ставке открывает панель с его карточкой, не уходя со страницы. Наведение на игрока показывает
мини-карточку (прибыль, 30 дней, в рынках, форма). В списке китов — имена, аватары и форма из Polymarket.

**Ставка и сигнал — всё о рынке.** Сценарии «сбудется / не сбудется / продать сейчас (с комиссией)»;
рынок: дата закрытия, объём (в т. ч. за сутки), ликвидность, разница цен, комиссия, цены исходов,
правила разрешения; «Кит сейчас» — его позиция, средний вход и прибыль по данным Polymarket;
«Кто ещё держит» — крупнейшие держатели с их входом и прибылью.

**Профиль кита.** Блок «По данным Polymarket» с кривой прибыли, лентой формы и открытыми позициями;
«что было бы при копировании» — за 30/90/180 дней или **за свои даты** (ставки, открытые в эти дни, и как
они закрылись на самом деле). Кривая «что было бы» теперь строится по дате закрытия ставок и
заканчивается ровно на итоге закрытых ставок.

## Что нового в v0.12 — живой интерфейс и решение за 5 секунд

**Экран обновляется сам.** Сервер держит с открытой страницей поток событий (`/api/events`, Server-Sent
Events). Новый сигнал появляется в списке сразу — с латунной подсветкой и, если включить значок динамика

**Карточка сигнала — решение за 5 секунд.**
- Шкала цен: где купил кит, где цена сейчас, сколько исход стоит по нашей оценке; закрашено — запас

- Кольцо обратного отсчёта до истечения сигнала.
- Ставка, «если сбудется / если нет» и две крупные кнопки; ниже — 3–4 главные причины. Все проверки,
  оценка ИИ, данные и новости — под «Подробнее».
- После покупки или пропуска сразу открывается следующий ждущий сигнал.

**Горячие клавиши** (работают при любой раскладке, в полях ввода отключены): `B` — купить, `S` —
пропустить, `J`/`K` — следующий/предыдущий сигнал, `Esc` — к списку, `G` затем `S`/`B`/`W` — сигналы,
ставки, киты, `?` — подсказка.

**Темы — как в меню Polymarket:** политика, спорт, киберспорт, крипто, финансы, культура, упоминания,
погода, экономика, технологии (+ «Разное», если Polymarket тему не указал). Один список на всё приложение:
настройки, рейтинг трейдеров, подписи, комиссии. Если у рынка несколько меток, побеждает более узкая
(киберспорт важнее спорта, финансы — экономики). При обновлении включённые темы сохраняют прежнее
поведение: финансы включаются, если была включена экономика (раньше они были её частью), киберспорт — если
спорт, упоминания и погода — если «Разное». Уже загруженные рынки один раз перечитываются, чтобы получить
новые темы (задача «Обновление тем рынков»); оценки китов по темам обновятся при следующем ночном пересчёте.

## Исправление v0.11.1: Data API v2

Polymarket 24 октября 2026 отключил старые методы Data API (HTTP 410). Переведены на v2:
журнал операций — `/v2/activity`, открытые позиции — `/v2/positions`, закрытые — `/v2/positions?status=CLOSED`
(везде курсор вместо offset: offset v2 отвергает с HTTP 400). Ответы v2 приводятся к прежнему виду, поэтому
сверка с Polymarket и split/merge работают как раньше; операции, записанные старым методом, повторно не
применяются. Диагностика проверяет сделки и позиции на кошельке кита из списка (или первого игрока
рейтинга), а при HTTP 400 показывает причину, которую пишет сервер.

## Что нового в v0.11 — скорость и надёжность связи с Polymarket

**Исправлен рейтинг трейдеров (ошибка HTTP 410).** Polymarket отключил старый метод `/v1/leaderboard` —
отсюда «ошибка HTTP 410» в диагностике. Теперь рейтинг берётся из `/v2/leaderboard`: до 1000 строк одним
запросом, дальше — по курсору. Первые 500 игроков приходят одним запросом и 10 минут хранятся в памяти,
поэтому «Показать ещё 50» открывается мгновенно. Если v2 когда-нибудь станет недоступен, приложение
попробует старый метод.

**Диагностика говорит, что именно случилось.** Подсказка теперь зависит от кода ответа: 410 — «метод
API отключён, обновите приложение», 429 — лимит запросов, 5xx — сбой у сервиса, 401/403/451 — доступ
ограничен (только здесь речь о сети или стране). Добавлены проверки сделок кошелька, журнала операций,
открытых и закрытых позиций, стакана и обоих потоков реального времени. У каждой проверки два времени:
рабочий запрос (по уже открытому соединению — так ходит приложение) и «с нуля» (с установкой защищённой
связи), плюс оценка: мгновенно / быстро / нормально / медленно.

**Потоки реального времени (WebSocket).** Раньше агент узнавал о ставке кита на следующем шаге опроса
(раз в 5 с плюс задержка обновления Data API). Теперь:
- *поток сделок* — лента сделок Polymarket (RTDS). Из неё берутся только сделки китов из вашего списка,
  остальные отбрасываются сразу и нигде не сохраняются. Сделка кита попадает к агенту через доли секунды;
- *поток стаканов* — канал market биржи: стаканы рынков, где есть ваши ставки, ждущие сигналы и позиции
  китов, обновляются сами. Агент берёт стакан из памяти (~10 мкс) вместо запроса `/book` (~100 мс).
  Для нового рынка первый стакан берётся запросом, и рынок сразу добавляется в поток.

Опрос остаётся страховкой (раз в 20 с, пока поток жив, и как раньше — если потока нет). Одна и та же
сделка из потока и из опроса записывается один раз и даёт один сигнал (сверка по транзакции, кошельку,
исходу, стороне, объёму и цене). Состояние потоков видно в «Диагностике» → «Реальное время».
Выключить потоки: `WF_STREAMS=off` в `.env`. Потоку нужен WebSocket: если прокси или фильтр его не
пропускают, агент автоматически работает опросом.

**Быстрее сеть и интерфейс.**
- Соединения с Polymarket держатся открытыми (задача «Поддержка соединений» раз в 45 с): первый запрос
  после простоя не тратит 2–3 круга на установку защищённой связи.
- Ограничитель частоты пропускает короткую пачку запросов без пауз (не превышая лимиты Polymarket):
  опрос 40 кошельков ждёт 1,2 с вместо 2,2 с.
- Сервер интерфейса: постоянные соединения (HTTP/1.1), сжатие (app.js 121 → 33 КБ), повторная загрузка
  файлов не скачивает их заново (ETag → 304). Ответ API по открытому соединению — около 1 мс.

**Про «20–50 мс на запрос».** Время запроса к Polymarket — в основном дорога до его серверов и обратно,
код приложения её не сокращает. Поэтому скорость получена другим путём: данные о сделках и стаканах
приходят сами (потоки), повторные запросы идут по открытым соединениям, а экраны читают локальную базу.
Реальные цифры для вашей сети покажет «Диагностика» → «Проверить сейчас».

## Что нового в v0.10

- **Экран «Диагностика»** (Настройки → Диагностика или нажать на блок состояния в меню): кнопка
  «Проверить сейчас» опрашивает Polymarket (каталог, поиск закрытых рынков, сделки, рейтинг, стаканы),
  Kalshi, Google News, Manifold и — если подключены — Telegram-бота, обозреватель блокчейна и букмекеров.
  Видно время ответа, ошибки и подсказки, состояние задач сбора и объём данных. «Скопировать отчёт» —
  текст без ключей и адресов кошельков, его можно прислать разработчику.
- **Поиск китов в рейтинге Polymarket** (экран «Добавить кита»): тема, период, сортировка по прибыли
  или объёму. Загружается только сам рейтинг (с v0.11 — `/v2/leaderboard`); история
  игрока скачивается, когда вы нажимаете «Проверить».
- **«Если бы вы копировали этого кита»** — в результате проверки и в профиле кита (30/90/180 дней):
  первая покупка кита в каждом исходе, наша цена — не лучше цены кита плюс 1¢, задержка — ваша реальная
  (медиана по сигналам) или 30 с, сумма и дневной лимит — из настроек, комиссии Polymarket, выход вслед
  за китом. Показаны итог, выигрыши, просадка, комиссии и результат самого кита на тех же ставках:
  разница — это то, что «съедает» задержка. Цены почасовые — это оценка, а не точный расчёт стакана.

## Что нового в v0.9

**Данные — только по вашим китам.** Система больше не просматривает всю ленту Polymarket и не собирает
данные по чужим кошелькам. Пока список китов пуст, она ничего не загружает. После добавления кита
загружаются только его ставки, рынки, цены, операции и переводы. Агент опрашивает кошельки китов
напрямую (до 40 кошельков), общая лента читается только при большем числе китов.
Автопоиск новых китов можно включить в «Настройки → Сбор данных» (по умолчанию выключен).
Там же показан объём данных и кнопка «Удалить данные по другим кошелькам» — для базы, накопленной
в прежних версиях.

**Больше информации в разделах.**
- «Киты»: процент выигрышей, число ставок, прибыль кита и доходность к вложенному, динамика за 12 недель,
  сверка с Polymarket.
- Профиль кита: прибыль, процент выигрышей, средняя ставка и цена входа, сколько держит ставку,
  открытые сейчас ставки кита и его закрытые ставки с итогом, ссылки на рынки Polymarket.
- «Мои ставки»: цена входа наша и кита, текущая цена, прибыль, комиссии, держит ли кит позицию.
- Страница ставки (нажмите на ставку): график цены с отметками входа кита и нашего, хронология,
  почему купили, «Открыть на Polymarket», «Продать сейчас».

**Новый дизайн.** Тёмная «морская» палитра с латунным акцентом, заголовки и суммы — Cormorant Garamond,
интерфейс — Golos Text; у каждого кита своя «печать». Шрифты загружаются с Google Fonts; без интернета
используются системные.

## Что нового в v0.8

**Важно при обновлении — сохранность базы.** Если в `.env` есть строка `WF_DB_URL=sqlite:///whalefollow.db`
(её содержал старый `.env.example`), в Docker база лежала внутри контейнера и пропадала при каждом
`docker compose up -d --build`. Теперь такой путь в Docker автоматически переводится в том `/data`.
Строку из `.env` лучше удалить. Ежедневные копии базы — в `/data/backups` (хранятся 7 последних).

**Точный учёт (блок 1)**
- Операции кошелька из журнала Polymarket (`/activity`): разделение токенов (split) и слияние (merge)
  учитываются в позициях как покупка/продажа всех исходов по 1/n — так и устроен контракт. События,
  где кит делал конвертацию (neg-risk), из оценки исключаются: восстановить их точно нельзя.
- Сверка с Polymarket (`/positions`, `/closed-positions`): наша прибыль кита против прибыли по данным
  Polymarket по каждой позиции. Вердикт в профиле кита и в результате проверки: совпадает (≤ 2%),
  небольшое (≤ 10%), заметное расхождение. Каждые сутки — для живого списка; при заметном
  расхождении приходит уведомление.
- Комиссии по действующим правилам Polymarket: платит тейкер, `акции × ставка × p × (1 − p)`, ставка
  по теме (крипто 0,07; спорт, экономика, прочее 0,05; политика, технологии 0,04; геополитика 0).
  Учитываются в решении и в виртуальных сделках. Таблица — в `whalefollow/fees.py`.
- Скорость сигналов: сколько секунд от сделки кита до сигнала (экран «Пробный режим»).

**Безопасность и удобство (блок 2)**
- Пароль на интерфейс: `WF_UI_PASSWORD` в `.env`. Вход на 30 дней, после 5 неверных попыток с одного
  адреса — пауза 10 минут. Смена пароля завершает все входы.
- Порт по умолчанию открыт только на этом компьютере (`127.0.0.1:8787`). Для доступа с телефона:
  задайте пароль и замените в `docker-compose.yml` на `"8787:8787"`; в интернет — только через HTTPS.
- Защита от подделки запросов с чужих сайтов: изменяющие запросы только в JSON, CORS закрыт.
- Запросы к интерфейсу обрабатываются параллельно (раньше — строго по одному).
- Telegram: под сигналом — кнопки «Купить» / «Пропустить», под выходом кита — «Держать» / «Продать»;
  команды `/status`, `/stop`, `/resume`. Принимаются только из вашего чата `WF_TELEGRAM_CHAT_ID`.
- Уведомление, если задача сбора данных упала 3 раза подряд, и когда снова заработала.

**Качество сигналов (блок 3)**
- Kalshi: открытые рынки сохраняются раз в 30 минут, похожий вопрос ищется по совпадению слов.
  Ключ не нужен.
- Букмекеры (только спорт): ключ `WF_ODDS_API_KEY` с the-odds-api.com. Обновление раз в 12 часов,
  1 кредит на вид спорта (`WF_ODDS_SPORTS`, `WF_ODDS_INTERVAL_H`). Вероятности без маржи букмекера,
  сопоставление с рынком по названиям команд.
- В сигнале: сколько других китов за и против этой стороны, крупная ли это ставка для кита
  (в сравнении с его обычной), докупает ли он к открытой позиции. Это подсказки, формула решения
  от них не меняется.
- Подстройка порога выгоды: на экране «Пробный режим» — что было бы при пороге 1–10% по всем
  сигналам с известным исходом (включая пропущенные), с учётом комиссии. Рекомендация появляется
  после 30 исходов, применяется кнопкой.

## Исправление v0.7.1: закрытые рынки

Каталог Polymarket (Gamma) без параметра `closed` отдаёт только открытые рынки. Из-за этого закрытые
рынки китов (большая часть истории) не находились: проверка тратила время на тысячи пустых
запросов, у позиций не было исходов, а виртуальные ставки в закрывшихся рынках не рассчитывались.
Теперь запросы по идентификаторам идут с `closed=any`, формат списка в запросе определяется
автоматически, а рынки, пропущенные раньше, догружаются сами (при проверке кита и каждые 30 минут).
Лимиты частоты подняты до документированных: каталог 25/с, сделки 18/с, цены и стаканы 80/с.

`whalefollow check` теперь замеряет скорость: сколько закрытых рынков нашлось пачкой и за сколько
загрузилась история цен. В результате проверки кита видно время каждого этапа.

## Скорость работы (v0.7)

Замеры на стенде: 300 игроков, 300 тыс. сделок, 1 млн точек цен; задержка каждого запроса к API 120 мс.

| Операция | Было | Стало |
|---|---|---|
| Проверка нового кита (6 тыс. сделок, 2,7 тыс. новых рынков) | 338 с, без прогресса | 20 с, с этапами и счётчиками на экране |
| Ночной пересчёт (скоринг) | 550 с | 19 с |
| Поиск связанных кошельков | 8,7 с | 1,8 с |
| Экраны («Киты», профиль, сигналы) | — | 0–10 мс |

Что изменилось:
- запросы к Polymarket идут параллельно (до 8 одновременно) с ограничением частоты на каждый API,
  рынки загружаются пачками по 50; недостающие — по одному;
- проверка кита работает в фоне: экран показывает этапы, можно уйти — по готовности придёт уведомление;
  повторная проверка того же адреса в течение 10 минут — мгновенно; кошелёк, уже загруженный поиском
  кандидатов, догружается только новыми сделками; история цен по 300 последним рынкам кита загружается
  сразу (без неё нельзя проверить, входит ли кит раньше рынка);
- при проверке одного кита читаются только его данные, а не вся база;
- у каждого потока своё соединение с базой: экраны не ждут, пока идёт пересчёт;
- планировщик разделён на четыре потока: агент, стаканы, сбор данных, расчёты — долгая задача
  не задерживает сигналы;
- расчёты переписаны векторно (маркет-мейкеры, синхронные сделки), пересечения рынков — через
  разреженные матрицы (scipy); добавлены индексы; история оценок старше 30 дней чистится.

## Интерфейс

Экраны по макету открываются в браузере на том же адресе, что и API:
`http://127.0.0.1:8787` (в Docker — `http://localhost:8787`). Исходники — `frontend/` (Svelte + TypeScript),
готовая сборка — `whalefollow/web/` (для запуска Node не нужен). Можно установить на телефон и включить
push-уведомления (см. «Что нового в v0.17»). Есть все экраны макета: первый запуск,
сигналы с таймером, карточка сигнала, мои ставки и решение «кит вышел», киты, профиль кита,
добавление кита, итоги со скачиванием отчёта (CSV), настройки, уведомления,
«Остановить всё», журнал решений и баннеры паузы и потери связи. На телефоне меню переезжает вниз.

## API (под экраны макета)

| Экран | Запрос |
|---|---|
| Сигналы | `GET /api/dashboard`, `GET /api/status` |
| Карточка сигнала | `GET /api/signals/{id}`, `POST /api/signals/{id}/confirm`, `POST /api/signals/{id}/skip` |
| Мои ставки | `GET /api/positions?status=open\|closed`, `POST /api/exits/{id}` `{action: hold\|sell}` |
| Киты / Профиль | `GET /api/whales`, `GET /api/whales/{id}`, `PATCH /api/whales/{id}` |
| Добавить кита | `POST /api/whales/check` `{address}` → `{job_id, state}`, `GET /api/whales/check/{job_id}` (этапы и счётчики), `POST /api/whales` `{entity_id, mode}` |
| Итоги | `GET /api/results?period=week\|month\|all` |
| Настройки | `GET /api/settings`, `PUT /api/settings` |
| Первый запуск | `POST /api/onboarding` `{jurisdiction_ok, risk_ack}` |
| Уведомления | `GET /api/notifications`, `POST /api/notifications/read` |
| Остановить всё | `POST /api/stop`, `POST /api/resume` |
| Журнал решений | `GET /api/journal` |

Причины решений отдаются простыми словами («Цена уже выросла, выгода пропала»), как на макете.

## Что ещё не подключено

1. **Проверка на живом API.** Из среды разработки Polymarket был недоступен. Поля Data API v2
   сверены с документацией, но разбор Gamma и CLOB нужно прогнать на реальных ответах.
   Все разборы собраны в `ingest/polymarket.py`.
2. **Внешние сервисы на живых ответах.** Разбор ответов Etherscan/Blockscout, Telegram, Reddit,
   журнала операций и позиций Polymarket, Kalshi и The Odds API сверен с документацией и проверен
   на образцах формата; из среды разработки эти сайты были недоступны. Если что-то не грузится —
   пришлите вывод `whalefollow check` и строки журнала.
3. **X (Twitter)** не подключён: нужен платный API. **CME FedWatch** — нет бесплатного API.
4. **Потоки WebSocket** (библиотека websockets) проверены на живом Polymarket: оба потока подключаются
   и присылают данные.
5. **PostgreSQL** поддержан в коде и миграциях, но проверялась только SQLite (проверка на обеих базах —
   этап 2).
6. **Реальные ставки.** Отключены намеренно.

## Как читать результаты бэктеста

`whalefollow backtest` печатает ROI по задержкам 5/30/120/600 с с 90% доверительным
интервалом, винрейт вместе со средней ценой входа, разбивку по корзинам цены и темам,
просадку и две базовые линии. Вердикт `continue: true` ставится, только если при
задержке 30 с набралось ≥ 20 сделок и нижняя граница ДИ ROI выше нуля. Это критерий
«стоп» из раздела 2 ТЗ.

## Docker

```bash
docker compose up -d --build                         # работа: http://localhost:8787
docker compose run --rm api whalefollow check        # проверка доступа к Polymarket
docker compose run --rm api python -m pytest -q      # автотесты
docker compose down --remove-orphans                 # остановить (данные сохраняются)
```
База хранится в томе `wf-data` и не теряется при перезапуске и обновлении.
